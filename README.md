# Mini NPU: MAC 패턴 판별기

표준 라이브러리만 사용하는 Python 3.8+ 콘솔 프로그램입니다. 패턴과 필터를 위치별 곱셈-누산(MAC)으로 비교하고, JSON 케이스를 `Cross` 또는 `X`로 판정합니다.

## 실행 방법

```powershell
python main.py
```

- `1`을 고르면 3×3 사용자 입력, `2`를 고르면 JSON 일괄 분석을 실행합니다.
- JSON 경로를 비우면 `main.py`와 같은 폴더의 `data.json`을 읽습니다.
- 사용자 입력 모드는 필터 A, 필터 B, 패턴을 순서대로 입력합니다. 각 행에는 숫자 3개를 공백으로 구분해 입력합니다.
- 열 개수 오류, 숫자 파싱 실패, NaN/무한대 입력은 유형별 안내를 출력한 뒤 행렬 전체를 다시 입력받습니다.
- `generate_pattern(N, "Cross")`와 `generate_pattern(N, "X")`는 각각 N×N 십자가와 X 패턴을 생성합니다.

## 구현 요약

- 입력은 2차원 리스트로 저장하며, `matrix[row][column]`으로 개별 값을 읽고 씁니다. JSON 모드는 5×5, 13×13, 25×25를 처리하고, 수동 모드는 3×3을 처리합니다.
- `mac_2d`는 누산값을 `0.0`으로 시작해 모든 위치에서 `pattern[i][j] * filter[i][j]`를 더하고 원시 합계를 반환합니다. 점수는 단위가 없는 유사도 합이며 별도 정규화나 분류 임계값은 적용하지 않습니다.
- `mac_flat`은 같은 입력을 길이 N² 배열로 평탄화해 처리합니다. 두 구현 모두 순수 반복문이며 NumPy 등 외부 라이브러리를 사용하지 않습니다.
- `normalize_label`은 입력 문자열의 앞뒤 공백을 제거하고 소문자로 바꾼 뒤, `+`/`cross`를 `Cross`, `x`를 `X`로 변환합니다. 알 수 없는 표기는 `None`으로 돌려 JSON 케이스 FAIL 사유가 됩니다.
- 정규화 함수를 분리해 수동 모드와 JSON 모드가 같은 표기 규칙을 쓰게 하며, 새 라벨을 추가할 때 한 곳에서 규칙을 확장할 수 있게 했습니다.
- JSON 케이스 키는 `size_{N}_{idx}` 정규식으로 검사합니다. 키에서 N을 추출해 `filters.size_N`을 선택하고, 입력/필터가 N×N인지 검증합니다. 잘못된 키, 필드, 라벨 또는 배열은 해당 케이스만 FAIL 처리합니다.
- 두 점수 차이의 절댓값이 `EPSILON = 1e-9`보다 작으면 `UNDECIDED`입니다. 비교는 엄격한 `<`이며 차이가 정확히 epsilon이면 큰 점수 쪽으로 판정합니다.
- epsilon은 절대 허용오차입니다. 제공 데이터의 최대 점수 52.9에 비해 약 1.9×10⁻¹¹ 수준이며, 십진 소수의 이진 부동소수점 표현에서 생기는 미세한 차이를 동점으로 취급하기 위한 값입니다. 입력 규모나 값의 크기를 크게 바꾸면 허용오차도 다시 정해야 합니다.

## 모드별 판정·동점 정책

두 모드는 **같은 `1e-9` epsilon 규칙**을 `classify_manual`과 `classify`에서 적용합니다. 차이는 표시 라벨과 expected 비교 여부입니다.

| 모드 | 점수 비교 결과 표시 | expected 비교 |
|---|---|---|
| 사용자 입력 3×3 | 점수 A가 크면 `A`, B가 크면 `B`, epsilon 동점이면 `판정 불가 (UNDECIDED)` | 없음 |
| JSON 일괄 분석 | Cross가 크면 `Cross`, X가 크면 `X`, epsilon 동점이면 `UNDECIDED` | `Cross`/`X` 판정이 정규화된 expected와 같을 때만 PASS. 동점은 expected가 Cross/X이므로 FAIL |

동점 자체의 규칙은 모드 간 차이가 없습니다. 사용자 입력 모드는 A/B라는 필터 이름으로 답하고, JSON 모드는 표준 라벨 및 PASS/FAIL까지 표시합니다.

## 성능 분석과 복잡도

각 크기에서 동일한 생성 패턴/필터를 사용합니다. 3회 예비 실행으로 워밍업한 뒤 MAC 함수를 10회 측정하고, 평균과 표본 표준편차를 ms로 출력합니다. 행렬 생성, 평탄화, I/O 시간은 측정에서 제외합니다. 표준편차는 짧은 측정의 시스템 부하 영향을 살피기 위한 참고값이며, 짧은 실행에서는 변동이 클 수 있습니다.

| 크기 | 단일 MAC 위치 수 N² | 측정 시간 |
|---|---:|---|
| 3×3 | 9 | 실행 시 2D/1D 평균±표준편차를 출력 |

한 번의 MAC은 N²개 위치를 한 번씩 방문하므로 시간 복잡도는 O(N²)입니다. 예를 들어 1000×1000은 한 번의 MAC에서 1,000,000개 곱셈-누산 위치를 처리합니다. 25×25의 625회보다 위치 수가 1,600배 많아져 Python 반복문에서는 CPU 연산 시간이 크게 늘어납니다.

메모리도 패턴과 필터마다 O(N²) 원소가 필요합니다. 이 프로그램은 비교 측정을 위해 2차원 리스트와 평탄화 복사본을 함께 보유하므로 1차원 비교 시 추가로 O(N²) 메모리를 씁니다. Python 리스트/객체의 메모리 오버헤드 때문에 원소 수만으로 실제 바이트 수를 단정할 수 없습니다.

대규모 입력의 최적화 우선순위는 실제 환경에서 프로파일링한 뒤 정합니다. 평탄화가 반복 계산에 도움이 되는지 측정하고, 복사본 메모리가 문제가 되면 `array('d')` 같은 연속형 저장소를 고려합니다. 데이터가 메모리보다 크면 블록 단위로 읽고 처리해 작업 집합을 제한할 수 있습니다. 메모리 매핑은 큰 파일을 순차/부분 접근할 때 유용할 수 있지만, 이 1000×1000 단일 패턴 예제에 자동으로 더 빠르다고 가정하지 않습니다.

이 표의 속도 측정은 **Python CPU 코드**에 대한 것입니다. 일반 CPU는 프로그램 흐름과 분기, 범용 작업에 강하지만 이 구현의 MAC 반복은 각 위치를 Python 루프가 순차적으로 처리합니다. NPU는 많은 MAC을 병렬 처리해 산술 처리량을 높일 수 있지만, 패턴·필터를 제때 공급할 메모리 대역폭과 데이터 재사용이 부족하면 연산 유닛이 기다리는 메모리 병목이 생깁니다. 실제 NPU는 전용 메모리 계층, 데이터 타일링, 스케줄링을 활용하며 이 콘솔 시뮬레이터는 이를 모델링하거나 CPU/NPU 실측 비교를 하지는 않습니다.

## 결과 리포트

### 제공된 `data.json` 판정

현재 파일의 6개 케이스에서 라벨 정규화와 epsilon 비교를 적용하면 **총 6개 중 PASS 3개, FAIL 3개**입니다. FAIL은 예상 라벨이 잘못됐다고 임의로 바꾸지 않고, 필터 점수가 epsilon 안에서 동점이라 구분할 수 없다는 정보를 보존합니다.

```text
size_5_1  | Cross=0.9 X=0.9 | 판정=UNDECIDED expected=X     | FAIL (판정 UNDECIDED != expected X)
size_5_2  | Cross=8.9 X=0.1 | 판정=Cross     expected=Cross | PASS
size_13_2 | Cross=7.5 X=7.5 | 판정=UNDECIDED expected=Cross | FAIL (판정 UNDECIDED != expected Cross)
[결과 요약] 전체 테스트: 6 | 통과: 3 | 실패: 3
실패 케이스:
- size_5_1: 판정 UNDECIDED != expected X
- size_13_2: 판정 UNDECIDED != expected Cross
- size_25_1: 판정 UNDECIDED != expected X
```

`size_5_1`과 `size_25_1`의 대각선 패턴은 두 필터 점수가 사실상 같고, `size_13_2`의 Cross 패턴도 X 필터의 중앙 가중치와 Cross 필터 점수가 같습니다. 일부 계산에서 `0.9`와 `0.8999999999999999`처럼 보이는 미세한 차이는 1e-9보다 작아서 동점 처리됩니다. 그래서 이 데이터의 FAIL은 단순 부동소수점 비교 실수보다 패턴/필터 점수 설계상 구분력이 부족한 사례입니다.

### 3×3 사용자 입력 예시

Cross 필터 A와 십자 입력을 쓰면 점수 A=5, X 필터 B 점수=1이므로 결과는 A입니다. 시간 숫자는 실행 환경마다 달라 실제 실행에서 측정됩니다.

```text
점수 A: 5 | 점수 B: 1
연산 시간: <실행 시 측정> ms | 판정: A
성능 분석 (워밍업 3회 후 10회 평균±표준편차): 3x3 2차원 <실측값> ms, 1차원 <실측값> ms, MAC 9회
```

### 실패 원인 분리 및 라벨 확장 시 확인 항목

- 데이터/스키마 문제: 키 `size_{N}_{idx}`, `input`/`expected` 필드, 정방형 배열 길이, 필터 라벨을 먼저 확인합니다. 키가 잘못되거나 행렬 크기가 다르면 해당 케이스만 FAIL으로 기록합니다.
- 로직 문제: 같은 작은 행렬을 손으로 계산한 점수와 `mac_2d` 결과를 대조하고, 2D/1D 함수가 같은 입력에서 같은 점수를 내는지 확인합니다.
- 수치 비교 문제: 점수 원시값의 차이를 보고 `abs(a-b) < 1e-9`인지 확인합니다. epsilon을 제거하면 부동소수점 잡음이 라벨 판정을 뒤집을 수 있습니다.
- `UNDECIDED`가 expected인 Cross/X와 같지 않으므로 PASS로 인정하지 않습니다. 두 필터가 실제로 구분되도록 데이터나 필터 가중치를 개선해야 합니다.
- 현재 라벨 표준은 Cross와 X입니다. 새 라벨을 추가할 때는 `normalize_label`의 별칭 규칙, 새 필터/패턴 샘플, 정상 판정, 동점, 미지원 표기 FAIL을 함께 확인해야 합니다.
- 실패 목록은 `케이스 ID: 판정값 != expected` 또는 해당 스키마/크기 검증 오류를 한 줄로 출력합니다. 총 테스트/통과/실패 수는 모든 케이스 처리 후 출력됩니다.
