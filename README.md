Mini NPU: MAC 패턴 판별기
1. 프로젝트 소개

Mini NPU는 외부 라이브러리 없이 Python 표준 라이브러리만 사용하여 구현한 MAC(Multiply-Accumulate) 기반 패턴 판별 콘솔 프로그램입니다.

컴퓨터는 사람처럼 그림의 모양을 직관적으로 인식하지 못합니다. 대신 패턴을 2차원 숫자 배열로 변환하고, 미리 정의된 필터와 비교하여 유사도를 계산할 수 있습니다.

이 프로그램은 십자가(Cross)와 X 패턴을 숫자 배열로 표현하고, 입력 패턴과 필터의 동일한 위치에 있는 값을 곱한 뒤 모두 더하는 MAC 연산을 수행합니다.

이를 통해 다음 내용을 직접 구현하고 확인하는 것을 목표로 합니다.

MAC 연산의 원리와 패턴 유사도 계산
2차원 배열을 이용한 데이터 관리
JSON 데이터 로드 및 스키마 검증
라벨 정규화와 부동소수점 허용오차 처리
2차원 및 1차원 배열의 MAC 성능 비교
입력 크기에 따른 시간·공간 복잡도 분석

프로그램에서는 두 가지 MAC 함수를 구현했습니다.

① mac_2d

2차원 리스트를 그대로 사용합니다.
누산값을 0.0으로 초기화합니다.
중첩 반복문으로 모든 위치를 순회합니다.
pattern[i][j] * filter[i][j]를 누적합니다.
최종 원시 점수를 반환합니다.

② mac_flat

2차원 배열을 길이 N²의 1차원 배열로 변환합니다.
단일 반복문으로 모든 위치를 순회합니다.
2차원 구현과 동일한 방식으로 MAC 점수를 계산합니다.

두 함수 모두 외부 라이브러리 없이 순수 반복문으로 구현했습니다.

점수는 단위가 없는 유사도 합이며 별도의 정규화나 분류 임계값은 적용하지 않습니다.

Cross: 중앙 행과 중앙 열을 1로 설정합니다.
X: 두 대각선 방향을 1로 설정합니다.

생성한 패턴은 사용자 입력 및 성능 측정에 재활용할 수 있습니다.

예를 들어 십자가는 +, cross, Cross 등으로 표현될 수 있습니다.

이를 통일하기 위해 normalize_label() 함수를 구현했습니다.

입력 라벨	정규화 결과
+	Cross

Cross	Cross
x	X
X	X

정규화 과정은 다음과 같습니다.

소문자로 변환
별칭에 따라 표준 라벨로 변환
지원하지 않는 라벨은 None 반환

수동 입력 모드와 JSON 모드에서 동일한 정규화 함수를 사용하므로 라벨 처리 기준이 일관됩니다.

지원하지 않는 라벨은 해당 JSON 케이스의 FAIL 사유로 기록합니다.

새로운 라벨을 추가할 경우 정규화 규칙뿐 아니라 해당 필터, 패턴 생성, 정상 판정, 동점 및 미지원 라벨 테스트도 함께 추가해야 합니다.

문제가 발생한 케이스만 FAIL로 처리하고 다음 케이스를 계속 분석합니다.

5. 판정 및 동점 처리 정책
5-1. EPSILON 기반 비교

컴퓨터의 부동소수점은 십진 소수를 정확하게 표현하지 못하는 경우가 있습니다.

예를 들어 수학적으로 동일한 값이라도 계산 결과가 다음과 같이 나타날 수 있습니다.

0.8999999999999999


단순히 두 값을 비교하면 미세한 표현 오차 때문에 잘못된 판정이 발생할 수 있습니다.

이를 방지하기 위해 다음 상수를 사용합니다.

python
EPSILON = 1e-9

차이가 EPSILON보다 작으면 UNDECIDED
차이가 EPSILON 이상이면 더 큰 점수를 선택
차이가 정확히 EPSILON인 경우에는 큰 점수를 선택

여기서 사용한 epsilon은 상대오차가 아닌 절대 허용오차입니다.

제공 데이터의 최대 점수 52.9를 기준으로 약 1.9×10⁻¹¹ 수준의 상대적인 크기입니다.

입력값의 크기나 데이터 규모가 크게 달라진다면 epsilon도 다시 검토해야 합니다.

특히 점수 규모가 매우 커지는 환경에서는 상대오차를 함께 사용하는 비교 방식도 고려할 수 있습니다.

5-2. 모드별 판정 방식

두 모드 모두 동일한 epsilon 규칙을 적용합니다.

차이는 결과를 표시하는 라벨과 expected 비교 여부입니다.

구분	사용자 입력 모드	JSON 분석 모드
비교 대상	필터 A / B	Cross / X
A 또는 Cross 우세	A	Cross
B 또는 X 우세	B	X
epsilon 동점	UNDECIDED	UNDECIDED
expected 비교	없음	있음
최종 결과	점수 및 판정	PASS / FAIL

JSON 모드에서는 판정 결과가 정규화된 expected와 정확히 일치할 때만 PASS입니다.

따라서 동점으로 UNDECIDED가 발생하면 expected가 Cross 또는 X이므로 FAIL 처리됩니다.

동점은 오답을 임의로 선택하지 않는다는 의미이며, 정상적인 분류 결과로 간주하지 않습니다.

7. CPU와 NPU의 차이

일반적인 CPU는 프로그램의 흐름 제어, 분기 처리, 다양한 범용 연산에 강점을 가지고 있습니다.

반면 NPU는 AI 연산에서 반복적으로 등장하는 MAC 연산을 병렬로 처리하여 높은 산술 처리량을 확보하도록 설계된 전용 프로세서입니다.

이 프로그램의 MAC 연산은 Python 반복문으로 각 위치를 순차적으로 처리합니다.

NPU는 다수의 MAC 연산을 동시에 처리할 수 있지만, 연산 유닛에 데이터를 충분히 공급하지 못하면 메모리 대역폭과 데이터 이동이 병목이 될 수 있습니다.

실제 NPU는 다음과 같은 기법을 활용합니다.

전용 메모리 계층을 통한 데이터 공급
데이터 타일링을 통한 메모리 재사용
연산 스케줄링을 통한 병렬 처리 효율 향상

이 콘솔 프로그램은 MAC 연산의 기본 원리를 이해하기 위한 시뮬레이터입니다.

실제 NPU의 하드웨어 구조나 CPU와 NPU의 실측 성능 차이를 모델링하지는 않습니다.

8. 결과 리포트
8-1. JSON 분석 결과

제공된 data.json의 6개 케이스를 분석한 결과입니다.

<pre>
전체 테스트: 6
통과: 3
실패: 3
</pre>

주요 케이스 결과:

케이스	Cross 점수	X 점수	판정	Expected	결과
size_5_1	0.9	0.9	UNDECIDED	X	FAIL
size_5_2	8.9	0.1	Cross	Cross	PASS
size_13_2	7.5	7.5	UNDECIDED	Cross	FAIL

나머지 케이스를 포함한 최종 결과는 다음과 같습니다.

text
[결과 요약]
전체 테스트: 6
통과: 3
실패: 3

실패 케이스:
- size_5_1: 판정 UNDECIDED != expected X
- size_13_2: 판정 UNDECIDED != expected Cross
- size_25_1: 판정 UNDECIDED != expected X

8-2. FAIL 케이스 원인 분석

이번 결과에서는 실패한 케이스를 임의로 PASS 처리하지 않고 실제 점수 비교 결과를 그대로 보존했습니다.

실패 원인은 데이터 자체의 구분력 부족에 있습니다.

① size_5_1

expected는 X입니다.
Cross와 X 필터의 점수가 각각 0.9로 계산됩니다.
두 점수의 차이가 EPSILON보다 작으므로 UNDECIDED가 발생합니다.
X가 expected이지만 판정 결과가 UNDECIDED이므로 FAIL입니다.

② size_13_2

expected는 Cross입니다.
Cross와 X 필터의 점수가 각각 7.5로 계산됩니다.
Cross 패턴의 중앙 위치와 X 필터의 중앙 가중치가 겹치면서 동일한 점수가 발생합니다.
두 필터 중 어느 쪽이 더 유사한지 구분할 수 없어 UNDECIDED로 처리됩니다.
expected가 Cross이므로 FAIL입니다.

③ size_25_1

expected는 X입니다.
대각선 형태의 입력 패턴에서 두 필터가 사실상 동일한 점수를 얻습니다.
epsilon 기준으로 동점 처리되어 UNDECIDED가 발생합니다.
expected와 판정 결과가 일치하지 않아 FAIL입니다.

이 사례들은 단순한 부동소수점 비교 실수로만 볼 수 없습니다.

실제로 두 필터의 점수 차이가 매우 작거나 동일하기 때문에 현재 필터 설계로는 해당 패턴을 명확하게 구분하기 어렵다는 점이 핵심입니다.

8-3. 실패 원인 분리 및 개선 방향

실패가 발생하면 원인을 크게 세 가지로 구분합니다.

① 데이터 및 스키마 문제

케이스 키가 size_{N}_{idx} 형식인지 확인
input 및 expected 필드 존재 여부 확인
입력 패턴과 필터의 크기 확인
필터 라벨이 지원되는 값인지 확인

② MAC 로직 문제

작은 행렬을 직접 계산한 결과와 mac_2d 결과 비교
동일한 입력에 대한 mac_2d와 mac_flat 결과 비교
배열 인덱스와 누산 과정 확인

③ 수치 비교 문제

두 점수의 원시값 확인
abs(score_a - score_b) < 1e-9 조건 확인
epsilon 적용 여부 및 경계값 비교 확인

이번 데이터의 FAIL 3건은 두 필터의 점수가 사실상 동일하여 구분력이 부족한 사례입니다.

이를 개선하려면 패턴의 특징이 Cross 필터와 X 필터에서 더 명확하게 다른 점수로 나타나도록 필터 가중치를 조정하거나 테스트 데이터를 보완해야 합니다.

단, expected를 임의로 변경하여 PASS를 만드는 방식은 사용하지 않습니다.

3×3 Cross 필터 A와 X 필터 B를 사용하고 십자가 패턴을 입력한 경우입니다.

text
점수 A: 5
점수 B: 1

연산 시간: 실행 환경에 따라 측정
판정: A


성능 분석은 워밍업 3회 후 10회 측정하며 2차원과 1차원 MAC의 평균 및 표준편차를 출력합니다.

9. 추가 검증 및 향후 개선 사항

프로그램의 안정성과 확장성을 위해 다음 항목을 확인할 수 있습니다.

잘못된 행렬 입력 시 전체 재입력 동작
숫자 파싱 실패 및 NaN/무한대 입력 처리
JSON 키 형식 오류 및 필수 필드 누락 처리
지원하지 않는 라벨의 FAIL 처리
epsilon 경계값보다 작은 차이와 정확히 같은 차이의 비교
동일 입력에 대한 2D/1D MAC 결과 일치 여부
새 라벨 추가 시 정상 판정, 동점 및 미지원 표기 테스트
여러 행렬 크기에서 실제 평균 연산 시간 비교

향후에는 실제 성능 측정값을 기반으로 배열 구조와 메모리 접근 방식을 비교하고, 대규모 데이터에 대한 블록 처리 및 타일링 기법도 추가로 탐구할 수 있습니다.

10. 프로젝트 마무리

이번 Mini NPU 프로젝트를 통해 단순한 배열 연산도 AI 패턴 판별의 기본 원리가 될 수 있다는 점을 확인했습니다.

특히 MAC 연산을 직접 구현하면서 곱셈과 누산의 구조를 이해했고, 라벨 정규화와 epsilon 기반 비교를 통해 실제 데이터 처리에서 발생할 수 있는 예외 상황과 부동소수점 오차를 다루어 보았습니다.

또한 JSON 데이터에서 발생한 FAIL을 무조건 수정하기보다 점수와 필터의 관계를 분석하여 원인을 구분하는 과정도 경험했습니다.

마지막으로 2차원과 1차원 배열의 성능 비교 및 O(N²) 복잡도 분석을 통해 데이터 크기가 증가할 때 연산량과 메모리 사용량이 어떻게 달라지는지 살펴보았습니다.

이 프로그램은 실제 NPU를 구현한 것은 아니지만, AI 연산의 핵심인 MAC의 원리와 병렬 연산이 필요한 이유를 이해하는 기초 시뮬레이터라는 점에서 의미가 있습니다.
